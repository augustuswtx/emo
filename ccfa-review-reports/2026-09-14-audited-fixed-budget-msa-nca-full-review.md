# 3. 论文概述与贡献图谱

论文提出一个针对多模态“质量/可靠性分数”的审计框架，并在 MFON 上实现训练期的可靠性感知辅助监督分配。作者先展示旧方案中的四类失败：样本分数被批量聚合、辅助损失过早约简、自由非负权重容易塌缩、范数代理随高斯扰动反向增大。随后，视觉和音频可靠性头通过 clean--mild--strong 特征扰动三元组学习排序；KL 和 InfoNCE 保持逐样本粒度；可靠性分数在每个批次内重新分配固定总量的辅助权重。MOSI 被诚实地定义为开发性证据，冻结后的 MOSEI 三种子矩阵作为跨数据集验证。结果显示 Learned 相对 Constant 的 MAE、Corr 和 Loss 均值方向较优，但幅度很小，分类指标混合，且没有稳定超过 repaired MFON。跨扰动审计进一步表明，高斯扰动识别不能迁移到多种未见扰动。

论文声称的四项贡献可归纳为：

1. 一个包含粒度、单调性、混杂、作用性和权重塌缩的五维审计框架。
2. 对旧 MFON 扩展方案的可复现失败分析。
3. 逐样本、精确固定批次预算的辅助损失分配机制。
4. MOSI 开发实验、MOSEI 冻结协议实验、跨扰动负面结果与成本评估。

最有价值的贡献是第 1 与第 3 项组成的“审计 + 控制”方法论。可靠性排序、高斯扰动、样本重加权或质量感知学习本身都不是新的。

## 6.1 主要优点

1. **科研诚信与证据边界处理得好。** 第 3--6、224--230、375--381 行反复说明 MOSI 测试诊断参与了方法开发，避免把开发集包装成未触碰验证集。MOSEI 的冻结协议和验证损失选 checkpoint 也交代清楚。
2. **固定预算设计是清晰且可审计的。** 第 164--203 行给出有限批次精确恒等式；代码也确实把权重归一到批均值等于基础系数。这能排除“动态方法只是减少了辅助损失总量”的替代解释。
3. **负面结果没有被隐藏。** 第 301--331 行报告未见扰动 AUROC 接近随机、视觉缺失不稳定、音频可检测但任务几乎不敏感；第 351--373 行对这些结果的解释相当克制。
4. **图 1 的信息架构优秀。** 主任务路径、训练期可靠性路径、冻结教师和无推理期门控的边界一目了然。
5. **成本结论克制。** 第 333--349 行没有把单次微基准的 1.46% 推理时差异宣称为加速，只保留参数量、训练延迟和显存的窄结论。
6. **论文问题意识比性能故事更强。** “一个叫 quality 的标量不等于可靠质量信号”是值得发表的方法论提醒，尤其适合做审计型论文的主线。

## 6.2 决定性问题

### M1. 同一样本内的排序监督不能证明不同样本间的干净分数可比较

证据：第 121--150 行的训练损失只约束每个样本自己的 `q_clean > q_low > q_high`；第 166--185 行却在一个批次的不同干净样本之间归一化 `q_i` 并据此分配权重。

技术问题：共享网络确实会产生同一数值尺度，但排序损失没有要求“样本 A 的 0.2 扰动”与“样本 B 的 0.2 扰动”接近，也没有校准不同内容、说话者、长度和情感强度引起的基线差异。模型完全可能学到“内容特征 + 扰动响应”，在每个样本内部保持正确排序，同时其干净分数的跨样本排序主要由内容或长度决定。音频长度相关约 0.22--0.24 已提示这一风险。

审稿扣分：这是核心机制层面的主要问题。高 AUROC 主要来自 clean/corrupt 区分，并不能直接验证用于批内分配的 clean-vs-clean 排名。

所需修复：至少增加三类证据。第一，按已知同一扰动严重度跨样本评估校准误差或 rank consistency；第二，用内容/说话者隔离的协议测试分数能否预测扰动严重度；第三，直接检验干净 `q_i` 与辅助目标质量（教师误差、正对可靠性、梯度一致性或验证损失贡献）的关系。若这些关系不成立，应将 `q` 改称 “Gaussian-degradation response score”，并放弃跨样本“可靠性”解释。

### M2. “高可靠性样本应获得更多辅助监督”的方向没有被最终实验验证

证据：第 205--220 行明确承认目标保真度假设没有证明，final-schedule Inverse/Difficulty-aware 和 Permuted 仍未完成。第 357--359 行也承认 Constant 不能证明方向。

审稿扣分：Learned vs Constant 只能说明两种训练方案的均值不同，不能把差异归因于“正确的可靠性-样本对应关系”。由于三种子效应很小，优化噪声、分数分布或正则化差异仍可能解释结果。

所需修复：在同一冻结配置上至少完成 Constant、Learned、Permuted 和 Inverse 四组多种子对照。最好再加入与辅助损失或梯度相关的 Difficulty-aware 对照。只有 Learned 稳定优于 Permuted 与 Inverse，才可声称分数对应关系和方向具有作用性；否则应把结论收缩为“非均匀分配有时改变训练结果”。

### M3. 效应量太小，三种子均值方向不足以支撑稳定有效性

证据：第 281--299 行中 Learned 相对 Constant 的 MOSEI MAE 改善约 0.47%，Corr 提升约 0.09%；各方法标准差约为 MAE 0.0062--0.0066、Corr 0.0011。分类指标有四项变差。Learned 相对 repaired MFON 的 MAE 和 Loss 仍略差。

审稿扣分：论文已经避免显著性声称，这是正确的，但“确认”或 “repeatable effect” 仍容易被读成稳定效果。只展示均值±标准差会掩盖配对种子是否一致。

所需修复：报告每个种子的完整指标和 Learned−Constant 配对差值，用配对点/连线替代或补充柱状图。至少增加到 5 个独立种子，给出配对 bootstrap 区间或适合小样本的效应量。若资源有限，应把 “confirmatory” 改为 “frozen-protocol cross-dataset replication”，并把结论限定为“descriptive mean direction”。

### M4. 完整方法与基线之间存在未拆开的可靠性监督差异

证据：P4 Constant 保留可靠性头训练和 reliability loss，只把分配设为均匀；repaired MFON 没有该附加训练目标。Learned vs Constant 隔离了分配，但 P4 系列与 MFON 的差异同时包含可靠性监督、参数和训练路径。

审稿扣分：当前三组设计能回答“Learned 分配是否优于同预算 Constant”，却不能完整回答“最终方法的哪个组件相对 MFON 有效”。更严重的是，P4 Constant 在 MOSEI 的 MAE/Loss 比 MFON 差，Learned 主要恢复了这部分损失。

所需修复：增加组件表：repaired MFON；逐样本损失实现但不训练可靠性头；训练可靠性头但 Constant 分配；Learned 分配。报告 task loss 与 reliability loss 的训练曲线，说明可靠性监督是否通过共享表征产生额外正则化或冲突。

### M5. 外部有效性与基线覆盖仍偏弱

证据：两个数据集均为英文视频情感分析，使用相近特征与同一个 MFON 骨干。没有在第二个骨干上验证，也没有与 QMF、SAM-LML、QA-MoE 等质量感知方法做同协议比较。

审稿扣分：若论文主张的是通用审计框架，单一骨干不足；若主张 MFON 实例上的方法，经验贡献又显得较窄。NCA 原创研究通常需要更完整的应用和比较证据。

所需修复：优先选择一个结构不同的骨干复用同一审计流程；其次在相同特征和扰动协议下加入至少一个公开质量感知方法。无需追求 SOTA，但要证明审计结论不是 MFON 特有实现错误。

### M6. 可靠性训练分布与真实“质量”概念不匹配

证据：第 301--331 行已经显示未见 timestep dropout、temporal shift 和视觉缺失接近随机或失效。特征层高斯噪声与真实背景声、ASR 错误、遮挡、跟踪失败并不等价。

审稿扣分：当前题目和摘要中的 “modality quality scores” 范围仍大于实际证据。论文的负面审计很有价值，但也削弱了最终方法作为质量估计器的定位。

所需修复：有两条合理路线。实验路线是用混合扰动训练并在真实媒体层扰动上测试；写作路线是把题目、方法名和主张收缩到 “auditing degradation scores for fixed-budget auxiliary allocation”。以当前结果，我更建议后者。

# 7. 可能缺失或需要强化的相关工作

1. **一般样本重加权与元重加权。** 当前正文把创新边界主要放在多模态质量感知研究中，尚未回答固定总权重、难例/易例分配、样本权重学习与本文的关系。需要增加一个短小但具体的小节。
2. **课程学习和 self-paced learning。** 论文曾使用 norm-based curriculum，并提出高可靠性优先分配；这与从易到难或难例挖掘的方向直接相关。应说明本文为何选择“可信目标优先”而非“难样本优先”。
3. **辅助任务权重与多任务优化。** 固定总预算下的四项辅助损失分配也属于多任务/辅助损失加权问题。需要说明本文是在样本维度而非仅任务维度分配，并讨论梯度冲突。
4. **SAM-LML 的技术对照。** 不应只写“它监督 attention ordering”；应比较监督对象、扰动类型、训练/推理使用位置、排序粒度、预算控制和鲁棒性目标。
5. **Moon et al. 的诊断边界。** 该工作检测推理期依赖；本文试图检测训练期作用性。最终 Permuted 对照未做之前，不宜写成已经完成了相同强度的 actionability audit。

# 9. 实验、统计与可复现性审计

- 数据集：MOSI/MOSEI 的开发/冻结边界处理合理，但二者同域，跨数据集并不等于跨场景或跨模态质量分布。
- 基线：Constant 是必要且设计良好的核心控制；缺少 final-schedule Permuted/Inverse、组件拆分和外部质量感知基线。
- 指标：MAE/Corr 作为回归主终点合理。Has0/Non0 和 Acc-5/7 的定义应在正文中给出阈值与零标签处理，而非只列名称。
- 统计：三种子只支持描述性结果。正文虽然承认这一点，但 Fig. 2 柱状图仍可能在截断纵轴下放大小差异。
- 配对设计：方法使用相同种子，理应报告 paired delta，而不只给各方法独立均值和标准差。
- 可靠性 AUROC：同一原始样本产生 clean/corrupt 对，建议同时报告 paired accuracy、每种严重度曲线与按说话者聚类的区间，避免把大量相关样本当作独立证据。
- 跨扰动审计：负面结果非常有价值，但只审计 Learned checkpoints；若讨论“鲁棒性”，还需比较 MFON/Constant/Learned 在相同扰动下的任务性能。
- 效率：固定一批样本和单次会话足以说明数量级，不足以说明速度。当前文字基本合格。
- 实现一致性：代码在权重归一化前对 reliability 执行 `detach()`，但第 166--203 行没有说明。读者会误以为任务辅助损失可以反向训练可靠性头。应把 `a_i^m` 写为基于 `stopgrad(q_i^m)`，并说明这是为了避免头通过操纵权重直接最小化目标。
- Oracle 定义：在最终 clean task path 中 `task_corruption_progress=0`，当前代码中的 severity oracle 会退化为全 1，即 Constant。正文不应暗示 final-schedule oracle 可直接沿用；需要重新定义一个对干净样本有意义的 oracle。
- 单元测试：37 项测试证明数学合同和实现路径，不证明统计有效性。正文已经说明这一点，建议把测试名称与版本放入补充材料。
- 可复现材料：代码、完整配置、预处理、特征来源、所有逐种子结果、checkpoint 选择日志和硬件环境应进入匿名工件。当前 “should release” 仍是计划，不是已提供证据。

# 12. AC / Meta-review

这是一篇比常见“加一个质量头再报性能”更成熟的稿件。作者已经做对了三件难得的事：承认开发过程中使用测试诊断；用严格预算守恒拆掉辅助权重总量混杂；公开跨扰动失败和文本主导。论文因此具有可信度，且审计型主线是成立的。

但目前证据仍没有闭合论文最核心的推理链：`同一样本内能检测高斯退化` → `不同干净样本的 q 可相互比较` → `q 较高意味着辅助目标较可靠` → `按 q 正向加权优于打乱、反向或难度加权` → `任务收益稳定存在`。现在第一步证据强，固定预算合同也强；第二、第三和第四步弱或缺失；第五步只有极小的描述性均值优势。因此，不能仅依靠诚实的限制声明来替代关键实验。

如果作者愿意将论文更彻底地定位为“质量分数审计与失败分析”，当前的负面跨扰动结果反而可以成为亮点，但仍需验证审计框架能否发现 clean-vs-clean 不可比性。若坚持把 P4 Learned 作为主要方法贡献，则必须完成 final-schedule 作用性对照和更强的配对统计。当前建议为大修；若是只能接收/拒绝的会议式评审，我会给弱拒绝。
