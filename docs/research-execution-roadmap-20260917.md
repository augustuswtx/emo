## 1. 唯一主问题与边界

**研究问题**：在多模态情感分析中，一个模态的某个样本是否适合获得更多辅助 KL 监督，应由什么证据决定？

已完成 P4 通过受控退化学习视觉/音频分数，并在 batch 内固定总预算分配 KL 与 InfoNCE。该分数能响应部分退化，却没有接受“该样本的辅助更新是否改善情感任务”的训练。C1 三种子事后审计显示视觉分数与 `-KL` 代理平均 Spearman 约 -0.315，音频仅弱正相关；C2 seed 1111 正向、置换、反向分配差异很小且 Corr 不一致；C5 seed 1111 的高零化敏感度分层没有 Learned 优势。这些结果否定当前强解释，却不直接测量一次辅助更新的任务效用。

**近期改造目标**：保留 MFON 骨干、原可靠性头、预算公式、训练日程和已有 checkpoint；第一版只为视觉/音频 KL 增加一个任务效用导向的分配选项，InfoNCE 先保持均匀。旧 P4 是对照和失败动机，不能改写其已完成结果。

### 低成本视觉效用代理（2026-09-21 服务器已运行）

`MFON/audit_visual_representation_proxy.py` 使用 meta batch 任务损失对视觉融合表示的梯度，与 aux batch 每个样本的视觉 KL 对表示的解析梯度做点积；解析梯度为 `softmax(student)-softmax(teacher)`。它以严格匹配 checkpoint 哈希和两批样本索引的 `task_gradient_step_seed1111_8pairs_20260921.json` 为参照，比较代理方向与已测量的视觉小步变化。该表示空间点积比逐样本参数梯度便宜，但不等价；只有同一批记录上方向一致，才值得进一步检查独立训练抽样与正式训练开销。

本地包 `../../mfon_visual_rep_proxy_20260921.tar.gz` 的 SHA-256 为 `dfb3171fe30b38835dea55e4e413ec06d203ee88d572fbcbfc23436cee385b6f`，包含审计脚本与检验解析 KL 梯度的 unittest。已通过 Python 3.8 语法检查，本地无 PyTorch。服务器日志显示八组审计完成，输出 `visual_rep_proxy_seed1111_8pairs_20260921.json`；按 `probe_status=ok` 的视觉小步计，代理方向与实测任务损失变化同号 `19/31`（61.3%）。同一批记录中 20/31 条实际小步有利，故恒判“有利”的基线已达到 20/31（64.5%）。单个 checkpoint 和同一八组顺序训练样本不足以估计泛化。**当前证据不足以将表示点积接入视觉 KL 分配或启动新训练。**

**逐组诊断（作者粘贴的服务器输出）**：八组正确数依次为 `[4/4,2/4,0/3,2/4,2/4,4/4,1/4,4/4]`；混淆表为真阳性 10、假阳性 2、真阴性 9、假阴性 10。若只用于“挑出有利样本”，预测有利的 12 条中 10 条确实有利，精确率 83.3%；但仅找到全部 20 条有利样本中的一半，且批间表现从 0/3 到 4/4。审计段用时 7.3 秒，PyTorch 已分配显存峰值约 1002 MiB，不包含完整模型加载或正式训练成本。这个后验诊断提示可研究保守筛选，但不能用同一 31 条调整阈值、宣称统计显著或推断最终 MAE/Corr 收益。

**下一步预先固定的复核**：在原先顺序审计涉及的前 256 个训练索引之外，用固定随机顺序抽取 24 个不重叠的 meta/aux batch 对（每批 4 个，最多 96 个视觉小步标签）。同一 checkpoint 上分别运行可逆 `proj_v.weight` 小步审计与表示代理，逐 pair 核对样本 ID，并以 `probe_status=ok` 为分母报告混淆表、预测有利比例、精确率、召回率、总体准确率和批间稳定性。主要判断是预测有利的精确率是否高于该新样本中有利小步的发生率，不能只看总体准确率；还要核对批内排序与额外计算成本。若新样本也无稳定筛选价值，放弃该廉价代理，改研究稀疏参数梯度标签上的轻量预测器或收束为审计型贡献。表示层点积忽略融合表示到共享参数的雅可比变换，本次失败不能推论参数空间效用不可预测。

本地已为两个原审计脚本增加 `--sample-order-seed 271828 --exclude-first 256` 选项；默认不传参数时保留旧数据顺序。随机排列使用独立 `torch.Generator`，排除前 256 个训练索引；每份 JSON 记录随机种子和排除数，代理脚本还逐组校验参照小步 JSON 的样本索引。包 `../../mfon_visual_proxy_random_holdout_20260921.tar.gz` 的 SHA-256 为 `be766e5b1b02f7ce8ebec5be9e09b9636a70cddd87b3bcb7cc552bba4204110d`，内含两个更新后的脚本和随机抽样单元测试；本地已通过 Python 3.8 语法与 `py_compile`，本地无 PyTorch。作者粘贴的服务器输出确认压缩包 SHA-256 校验成功、三个 `test_task_aligned_step.py` 单元测试通过。随机 24 组小步审计从 PID 1485 启动，并已输出 `saved step audit to .../task_gradient_step_seed1111_random24_20260921.json`；日志记录审计段耗时 `159.9654562000651` 秒、PyTorch 已分配显存峰值 `1175.5478515625 MiB`。作者所贴为日志末段，仍需读取完整 JSON 汇总有效条数、视觉预测–实际方向一致率和样本索引；表示代理在该组上的结果尚不存在。tar 的 macOS provenance 扩展头被忽略提示未阻止测试。抽样设计与上述主要判断在查看随机结果之前确定。

## 3. 公平比较协议（正式训练前冻结）

- **主终点**：MAE 越低越好、Corr 越高越好；其他分类指标完整报告，不挑选。
- **控制变量**：同一数据划分、seed、单模态编码器、MFON 骨干、25 epoch、warmup、优化器、checkpoint 选择规则和预算系数。中心比较只改变 KL 分配分数；可靠性损失要么在各组都开启，要么在各组都关闭。
- **预算核对**：逐 epoch 报视觉/音频实际平均 KL 权重、关闭辅助的 batch 比例、实际辅助损失。若方法可选择在某些 batch 关闭 KL，必须加入使用相同关闭掩码的 uniform 对照。
- **归因**：C4 per-sample-only 用于区分可靠性损失与分配本身；新分数的 Permuted/Inverse 用于测试样本对应关系和方向。
- **验证边界**：MOSEI 的旧 test 总表和 C5 分层已参与设计，不能充当新方法的未触碰确认集。效用学习只用训练数据内部的分离 batch；验证集只按冻结规则选择 checkpoint。独立确认设置须在正式实验前指定。
- **计算约束**：服务器曾有约 11–12 GiB 可用盘但会变化；新训练前重新确认空间、GPU 进程、日志名和 checkpoint 目标不冲突。一个 GPU 训练完成并核实后再启动下一个。

## 4. 三种可能结果与论文写法

| 实际结果 | 小论文可以写什么 | 大论文如何收束 |
|---|---|---|
| 任务效用可预测，新分配稳定优于匹配控制 | 任务导向的预算约束辅助监督分配；旧退化分数作为失效边界 | 第三章审计，第四章新方法，第五章独立验证与应用边界 |
| 效用可预测，但最终性能收益小或不稳 | 严格报告机制信号与性能不一致；不宣称普适性能提升 | 以可信性评估、优化边界和失败条件为主线 |
| 效用测量不稳定/成本过高 | 不进入大规模重训；写审计与可行性边界 | 第四章改成条件辅助学习的负面结果/替代轻量策略，需和导师确认贡献要求 |

下周开题要承诺的是**问题、方法路线、验证协议和可调整的备选路径**，不是尚未获得的正向结论。大论文具体结构见 [开题与章节方案](thesis-proposal-outline-20260917.md)。
