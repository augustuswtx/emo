> 状态：本地规划已完成；服务器新方法的梯度审计和训练均未运行。本文的“通过条件”是事先确定的决策规则，不是已有实验结果。服务器由作者手动操作；本地文件不会自动同步或启动 GPU 任务。

## 1. 唯一主问题与边界

**研究问题**：在多模态情感分析中，一个模态的某个样本是否适合获得更多辅助 KL 监督，应由什么证据决定？

已完成 P4 通过受控退化学习视觉/音频分数，并在 batch 内固定总预算分配 KL 与 InfoNCE。该分数能响应部分退化，却没有接受“该样本的辅助更新是否改善情感任务”的训练。C1 三种子事后审计显示视觉分数与 `-KL` 代理平均 Spearman 约 -0.315，音频仅弱正相关；C2 seed 1111 正向、置换、反向分配差异很小且 Corr 不一致；C5 seed 1111 的高零化敏感度分层没有 Learned 优势。这些结果否定当前强解释，却不直接测量一次辅助更新的任务效用。

**近期改造目标**：保留 MFON 骨干、原可靠性头、预算公式、训练日程和已有 checkpoint；第一版只为视觉/音频 KL 增加一个任务效用导向的分配选项，InfoNCE 先保持均匀。旧 P4 是对照和失败动机，不能改写其已完成结果。

## 3. 公平比较协议（正式训练前冻结）

- **主终点**：MAE 越低越好、Corr 越高越好；其他分类指标完整报告，不挑选。
- **控制变量**：同一数据划分、seed、单模态编码器、MFON 骨干、25 epoch、warmup、优化器、checkpoint 选择规则和预算系数。中心比较只改变 KL 分配分数；可靠性损失要么在各组都开启，要么在各组都关闭。
- **预算核对**：逐 epoch 报视觉/音频实际平均 KL 权重、关闭辅助的 batch 比例、实际辅助损失。若方法可选择在某些 batch 关闭 KL，必须加入使用相同关闭掩码的 uniform 对照。
- **归因**：C4 per-sample-only 用于区分可靠性损失与分配本身；新分数的 Permuted/Inverse 用于测试样本对应关系和方向。
- **验证边界**：MOSEI 的旧 test 总表和 C5 分层已参与设计，不能充当新方法的未触碰确认集。效用学习只用训练数据内部的分离 batch；验证集只按冻结规则选择 checkpoint。独立确认设置须在正式实验前指定。
- **计算约束**：服务器曾有约 11–12 GiB 可用盘但会变化；新训练前重新确认空间、GPU 进程、日志名和 checkpoint 目标不冲突。一个 GPU 训练完成并核实后再启动下一个。

## 4. 三种可能结果与论文写法

| 实际结果 | 小论文可以写什么 | 大论文如何收束 |
|---|---|---|
| 任务效用可预测，新分配稳定优于匹配控制 | 任务导向的预算约束辅助监督分配；旧退化分数作为失效边界 | 第三章审计，第四章新方法，第五章独立验证与应用边界 |
| 效用可预测，但最终性能收益小或不稳 | 严格报告机制信号与性能不一致；不宣称普适性能提升 | 以可信性评估、优化边界和失败条件为主线 |
| 效用测量不稳定/成本过高 | 不进入大规模重训；写审计与可行性边界 | 第四章改成条件辅助学习的负面结果/替代轻量策略，需和导师确认贡献要求 |
